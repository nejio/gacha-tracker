# 召喚録 - 課金管理台帳

スマホゲームの課金額・ガチャ結果・天井(保証)カウンター・ガチャ予定と予算を、複数端末で同期しながら管理するPWAです。

## 機能

- 月次・累計の課金額表示(アプリ別グラフ付き)
- 課金(円→石)と ガチャ消費(石を使って引く)を別記録にし、アプリごとの石残高を自動計算
- 無償石(ログインボーナス・配布)の記録に対応(残高は増えるが課金額には計上されない)
- バナーごとの天井(保証)カウンター管理。バッチ内の何回目で入手/すり抜けたかを指定でき、正確に反映
- すり抜けの記録(最高レアは出たが目的ではない)。天井リセット+「次回確定」フラグ管理
- ガチャスケジュールカレンダー×予算計画。ゲームのガチャシステム(50/50型・天井交換型)を選ぶと期待費用・最大費用を厳密に計算
- 予定→実績の接続。予定から記録へジャンプでき、計画額に対する消費実績を表示
- 記録の削除時に残高・天井・保証状態を巻き戻し
- **23タイトルのゲーム別マスターデータ**を同梱。アプリ登録時にゲームを選ぶだけで、確率・天井・通貨レート・バナーが自動設定される
- Googleアカウントでログインし、Firestoreを通じて複数端末で同期
- PWA対応(ホーム画面に追加してアプリのように利用可能)

## セットアップ手順

### 1. 依存関係のインストール

```bash
npm install
```

### 2. Firebaseプロジェクトの作成

1. [Firebase Console](https://console.firebase.google.com/) で新規プロジェクトを作成
2. 「Authentication」→「Sign-in method」で **Google** を有効化
3. 「Firestore Database」を作成
4. 「プロジェクトの設定」→「マイアプリ」でウェブアプリを追加し、表示された設定値を控える

### 3. 環境変数の設定

```bash
cp .env.example .env
```

`.env` にFirebaseの設定値を記入します。

### 4. Firestoreセキュリティルールの適用

`firestore.rules` の内容を Firebase Console の Firestore「ルール」タブに貼り付けて公開してください。

### 5. ローカルで起動

```bash
npm run dev
```

### 6. GitHub Pages へのデプロイ

`vite.config.js` の `base` をリポジトリ名に合わせて変更してから:

```bash
npm run build
npm run deploy
```

デプロイ後、Firebase Console の Authentication → Settings →「承認済みドメイン」に
`<ユーザー名>.github.io` を追加しないとログインできません。

## データ構造(Firestore)

```
users/{uid}/apps/{appId}
  - name, currencyName(石の呼び方), currencyBalance(自動計算), yenPerCurrency(1石あたりの円)

users/{uid}/banners/{bannerId}
  - appId, name, pityMax, pityCurrent, costPerPull, guaranteed(すり抜け後の確定フラグ)

users/{uid}/purchases/{purchaseId}   … 課金/無償獲得の記録
  - appId, date, amountYen, isFree, currencyGained, note

users/{uid}/pulls/{pullId}           … ガチャ消費記録
  - appId, bannerId, scheduleId, date, pullCount, currencySpent, targetItem,
    obtained, lost, obtainedAtPull, isPityTriggered, pityBefore, guaranteedBefore, note

users/{uid}/schedules/{scheduleId}   … ガチャスケジュール
  - appId, name, startDate, endDate, costPerPull, system(確率モデル),
    targetOptions, selectedTargetId, plannedYen

users/{uid}/budgets/{budgetId}       … 月次予算
  - month("2026-07"形式), amountYen
```

## 期待値計算について

`src/utils/calc.js` の `systemPulls` が3種類のモデルに対応しています。

- **fiftyFifty(原神/スタレ系)**: 基礎排出率・ソフト天井・ハード天井から最高レア1体の期待回数を厳密計算し、
  すり抜け保証込みで `E5★ × (2 - ピックアップ率)` を目的1体の期待回数とする。最大は天井×2
- **spark(プリコネ/グラブル系)**: `Σ i·r·(1-r)^(i-1) + S·(1-r)^S`。最大は交換天井S
- **manual**: 期待回数を手動入力(旧データの後方互換)

いずれもモンテカルロシミュレーション(20万試行)と誤差0.1%未満で一致することを確認済みです。

### 追加・修正

`GAME_PRESETS` に1件追加するだけでUIは自動対応します。特殊な保証仕様は `maxPullsOverride`
で実際の保証回数を指定できます(例: エンドフィールドは80連★6確定だが120連でPU確定)。

円換算レートはまとめ買いや初回ボーナスを使わない標準的な購入を基準にした概算です。
仕様変更やキャンペーンで変動するため、すべての値はアプリ内で編集できます。

## 残高・天井の計算方式

残高と天井カウンターは**値を保存せず、記録から毎回計算**しています。
そのため記録を削除・編集しても、常に自動で整合が取れます。

```
石残高 = 開始時の残高 + 開始日以降の獲得 − 開始日以降の消費
天井   = 開始時のカウンター から、開始日以降の記録を古い順に再生した結果
```

計算は `src/utils/calc.js` の `computeBalance` / `computePity` にあります。
値がズレた場合は、管理タブの「開始時の残高」「開始時の天井」を直せば全体が再計算されます。

### 履歴の分割読み込みへの備え

計算は「チェックポイント(基準時点の状態)＋それ以降の記録」という形にしてあり、
現在は開始時点(`openingBalance` / `openingPity` / `openingDate`)を唯一のチェックポイントとして使っています。

記録が増えて全件読み込みが重くなったら、「月末時点の残高・天井」を保存した
スナップショット文書を用意し、それをチェックポイントとして渡すだけで、
`computeBalance` / `computePity` はそのまま使えます。関数の作りを変える必要はありません。

### ガチャ記録の `outcome`

天井の再生には「ユーザーが入力した結果」が必要なため、記録に `outcome`
(`none` / `obtained` / `lost`)を保存しています。`obtained` は天井到達による自動確定を含む
表示用の結果なので、再生には使いません(`pullOutcome` が古い記録との互換も吸収します)。

## バージョン表示

管理タブの最下部に、バージョンとビルド日時が表示されます。
デプロイした版が反映されているかの確認に使えます。

バージョンは `package.json` の `version` を参照しており、`vite.config.js` の `define` で
ビルド時にアプリへ埋め込まれます。更新する際は `package.json` の値を書き換えてから
`npm run build` してください。ビルド日時は自動で入ります。

```
npm version patch   # 1.1.0 → 1.1.1(バグ修正)
npm version minor   # 1.1.0 → 1.2.0(機能追加)
```

## 既知の制限

- 引いたのに記録し忘れると残高・天井がズレます。管理タブの開始値を直せば全体が復旧します
- 月跨ぎのガチャは「開始月」の予算に計上されます
- 天井の再生は記録の日時順に依存します。複数端末の時計が大きくずれていると順序が狂う可能性があります
